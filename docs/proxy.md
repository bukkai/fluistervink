# De proxy: toegang, kosten, statistieken en delen

Naslag bij `worker/`, verplaatst uit `CLAUDE.md` op 12 nov 2026; daar staat per onderwerp nog één regel. De proxy (`worker/index.ts`) houdt de API-sleutels buiten de app; welke routes er zijn en wat ze doorlaten, staat in `CLAUDE.md` onder API-sleutels. Houd dit bestand gelijk met de code, net als `#privacy`.

## Toegang

geen accounts, geen e-mailadres en geen code nodig (`docs/plan-laagdrempelig.md`). Zonder code meldt de app zich bij het openen onzichtbaar aan als installatie (`/api/install`, `worker/install.ts`, in de app `src/lib/install.ts`): een willekeurig id, en eerst bewijzen dat het de echte app is, in de Android-app met Play Integrity (Google; `IntegriteitPlugin.java`), anders of als dat mislukt met Cloudflare Turnstile. De proxy geeft dan een ondertekend token (HMAC, geheim `INSTALL_SECRET`); de installatie heet daarna "app-3f9a2b1c" en werkt verder als een tester (snelheidslimiet, verbruik, feedback). Bij Instellingen kan de gebruiker een naam opgeven (niet verplicht, `/api/install/name`, in KV bij de installatie), die de eigenaar op Developer naast de installatienaam ziet. Elke installatie staat in KV `TESTERS` (`install/<id>`) en is op Developer af te sluiten en daarna uit de lijst te halen (`/api/testers`, alleen de eigenaar; het record blijft, met `hidden`, anders werkt het token weer). Instellingen: geheimen `INSTALL_SECRET`, `TURNSTILE_SECRET`, `PLAY_SERVICE_ACCOUNT`, vars `TURNSTILE_SITE_KEY`, `PLAY_PROJECT_NUMBER`; zonder staat die weg uit. Plafond en daglimiet van het tegoed stelt de eigenaar in bij OpenAI en Anthropic zelf. Alleen de eigenaar heeft een code (`ACCESS_CODE`; de proxy noemt hem dan "eigenaar": Developer, Statistieken, kosten, feedback ophalen, geen snelheidslimiet), in te vullen bij Instellingen onder "Code van de ontwikkelaar" en daarna in localStorage. Testercodes (`ACCESS_CODES`, uitnodigen vanaf Developer, `#code=`-links) zijn op 9 nov 2026 weggehaald: een app met een oude code gooit die bij de eerste 401 weg en meldt zich aan als installatie. De naam van de installatie gaat mee in de JSON-export en de feedback.

## Kosten

de proxy telt bij elk verzoek aan OpenAI en Anthropic het verbruik (tokens uit het `usage`-blok, bij `whisper-1` seconden audio) per dag, tester, omgeving, sessie (header `X-Session` van de app; de testset zonder) en model, in D1 (binding `USAGE`, `worker/usage.ts`; geen KV, want die kan niet veilig optellen en heeft weinig schrijfacties). Ook de testset telt online mee: `npm run testset` zet `FLUISTERVINK_USAGE_ONLINE`, waarmee de dev-server de echte D1 gebruikt (`vite.config.ts`, vraagt `wrangler login`); gewone `npm run dev` telt lokaal. De kaart Kosten op Developer (`/api/usage`, alleen de eigenaar) rekent het met de prijstabel in `src/lib/costs.ts` om naar dollars: vandaag, deze en vorige maand, per tester en de duurste sessies. Prijzen veranderen: de tabel heeft een datum en bron. Ter controle staat ernaast de echte rekening van deze maand (`/api/billing`, `worker/billing.ts`): de Costs API van OpenAI en de Cost API (Admin API) van Anthropic, elk met een eigen beheersleutel als geheim in de proxy (`OPENAI_ADMIN_KEY`, `ANTHROPIC_ADMIN_KEY`, optioneel; de Admin API van Anthropic werkt alleen met een organisatie, niet met een persoonlijk account). Alleen de kosten van Fluistervink: het OpenAI-project `OPENAI_PROJECT_ID` en de Anthropic-workspace `ANTHROPIC_WORKSPACE_ID` (vars in `wrangler.jsonc`, voor beide omgevingen; zonder id de hele organisatie, dus ook andere projecten). De proxy haalt de rekening hooguit eens per uur op en bewaart hem in KV (`TESTERS`); mislukt het (de Costs API van OpenAI staat maar 10 verzoeken per minuut toe), dan toont Developer de laatst bekende stand met de fout erbij en probeert de proxy het pas na een minuut opnieuw. Developer vergelijkt vanaf de eerste getelde dag van de maand.

## Statistieken

pagina `#statistieken` (`src/lib/Statistics.svelte`, alleen de eigenaar, in het menu naast Developer): gebruikers per dag, en per week actief, nieuw, terug en weggevallen, plus sessies en uitspraken. Geen nieuw gegeven: de proxy vat de usage-tabel samen per dag en tester (`/api/stats`, `activitySince` in `worker/usage.ts`, zonder de testset), de app rekent (`src/lib/stats.ts`). "Gebruiken" = minstens één uitspraak in een sessie. Alleen totalen op het scherm, geen namen; eigen gebruik standaard niet meegeteld. Meer (duur, regio, functies, openen zonder inspreken) pas met een anonieme samenvatting per sessie, met `#privacy` erbij.

## Delen met de ontwikkelaar

gestopte sessies (uitspraken, transcripten, LLM-uitvoer, nagelopen waarnemingen, prullenbak, feedback en het log van die periode) gaan automatisch naar de proxy, die ze per tester in KV bewaart (`/api/feedback`, `worker/feedback.ts`, binding `FEEDBACK`). Opnieuw na een wijziging (hash per sessie), bv. na het nalopen; mislukt het, dan bij de volgende gelegenheid (opstarten, schermwissel, weer online). Alleen na toestemming: het hoofdscherm vraagt het één keer (ook aan wie de app al had), daarna aan/uit bij Instellingen (`src/lib/ShareSettings.svelte`). Opnames alleen als de gebruiker dat apart aanzet. Alleen de eigenaar kan ophalen: `npm run feedback -- pull` zet per tester een export in `testset/feedback/<tester>.json`, direct bruikbaar voor `npm run testset`; `npm run feedback -- notes` toont de nieuwe feedback (`--alle`: ook verwerkte) en `npm run feedback -- verwerkt` markeert die daarna als verwerkt (ook op het scherm Developer, waar de eigenaar de feedback van alle testers leest; `/api/feedback/notes`, verwerkte id's in KV `TESTERS`). Verwerkt verbergt alleen; de gedeelde sessies blijven (testset), samengevat in `NOTES.md`. `npm run feedback -- wipe <tester>` wist alles van een tester (online en lokaal). Zie `src/lib/share.ts` en `scripts/feedback.mjs`.
